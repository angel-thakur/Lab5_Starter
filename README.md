Check Your Understanding:
1. You could use a unit test to test certain functionality of sending and recieving a message but not the whole thing comrpehensively. The entire process of a message function involves a lot of layers like the UI, the API call, delivery to the recieving user, and more. A unit test would not be the best tool to test if all of these elements are working properly.
2. This is a very good use case for a unit test. It is a smaller feature that does not rely on several layers of implementation on the code stack. Instead, it is a deterministic feature with either a success or a failure involved (should allow all messages <= 80 characters, should not allow anything greater).
